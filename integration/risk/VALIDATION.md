# Risk 검증 결과와 남은 검증

현재 구현과 과거 검증 조건을 구분한다. 운영 DB·NCP 배포·자동 동기화 활성화는 수행하지 않았다.
계산식·업무 API 경로·3거래일 만료 정책·종목별 원자성은 유지하며 이번 Python 운영 기능에 추가 테이블·컬럼은 없다.

## Python 현재 검증

- **142개 회귀 테스트 통과**. 합성 가격·달력과 모의 KIS를 사용하며 실제 키·네트워크 없이 실행했다.
- 독립 계산 기대값·등급 경계·공통 수익률·99% 표본·연속 공백·3/4거래일 만료·정정·원자성·버전·보존 마이그레이션 포함.
- 실제 APScheduler 시작·즉시 복구·KST·단일 실행·종료·재개·시도 상한·품질 실패 반복 방지 포함.
- 공유 키의 401/503·health 생존·성공 계산 시각과 게시 시각 분리·배치 중 API 응답·수동 CLI 잠금 감지 포함.
- WAL 읽기·쓰기·실시간 일관된 백업·동일 날짜 원자 교체·7개 회전·백업 실패 후 백업만 재시도 포함.
- TestClient의 httpx 관련 폐기 예정 경고 1개가 있으나 테스트 실패는 아니다. 운영 API 경고나 계산 오류는 아니다.

로컬 Linux Docker 이미지 빌드 및 별도 named volume·루프백 포트에서 다음을 확인했다.

1. 초기 health·실제 HTTP 인증·등급·단일 종목 패키지 계약.
2. UID/GID 10001 사용자로 /data 쓰기·WAL·DB integrity_check·일관된 백업.
3. 다른 Linux 프로세스가 소유한 배치 잠금을 health의 batch_running이 감지.
4. 백업 CLI와 컨테이너 재시작·재생성 후 같은 등급·가격 기준일·버전 보존.

이 컨테이너 검증은 합성 데이터이며 KIS 호출은 0회다. 소유 라벨로 확인한 임시 컨테이너·볼륨만 정리했다.
도구는 Python 저장소 tests/integration/verify_risk_container.py이며 실제 NCP 볼륨 검증과 구분한다.

## MARIA 기존 검증 증적

MARIA 전체 1,436개 테스트 통과는 이전 실행 기록이다. 이번 Python 운영 기능 작업에서 전체 MARIA 테스트를 다시 실행하지 않았다.
기존 연동 신규 테스트 27개는 다음과 같다.

| 구분 | 개수 | 범위 |
| --- | ---: | --- |
| StockRiskGradeMariaDbTest | 12 | MariaDB 실제 트랜잭션·PK/FK·동시 INSERT/UPDATE·날짜/버전·멱등·충돌·JDBC 시간·DML 롤백·잠금·교착·이관·동기화 상태 |
| RiskClockConfigTest | 1 | 기존 Clock·위험등급 시계 분리 |
| KrxTradingCalendarTest | 2 | 합성 경계·누락·해시 거절 |
| RiskGradeServiceTest | 3 | 모의 Mapper의 버전 0·만료·세션 차단 |
| PythonRiskClientTest | 3 | 모의 HTTP의 JSON·오류 계약 |
| RiskGradeSyncServiceTest | 3 | 모의 부분 게시·재시도·보존 |
| RiskSyncCoordinatorTest | 3 | 모의 주기·재시도·마감·휴장일·소진 |

12개는 실제 DB 의존, 나머지 15개는 DB 없는 검증이다.
이후 실제 Uvicorn·MARIA RestClient·임시 DB를 연결한 HTTP 통합 3개도 통과했다.
동일 응답·정정·부분 게시, 실제 503·재시도·EXPIRED 제외, 전역 UTC/위험등급 세션 KST를 검증했다.
이 3개는 공유 키 인증 추가 전 기록이다. 현재 인증 포함 재검증은 아래 결과를 따른다.

2026-10-30 추가 검증에서는 새 임시 MariaDB 컨테이너(127.0.0.1:33380/risk_test)와 실제 Python HTTP를 사용했다.
기존 운영 DB 및 기존 테스트 컨테이너에는 접속하지 않았다. 추가 SQL·마이그레이션·테이블·컬럼은 없다.

- 위험등급 테스트 **20개 통과**: 시계 1, 달력 2, HTTP 클라이언트 4, 서비스 9, 실제 HTTP+DB 통합 4.
- HTTP 통합: 인증 누락·잘못된 키, 인증 실패 중 기존 값 보존·장애 재시도 미예약·키 복구 후 멱등 수신.
- 기존 실제 HTTP 흐름의 부분 게시·동일 버전·정정 버전·503·만료 제외·KST/UTC 저장 검증도 재통과.
- 최초 실행은 Windows 자식 프로세스의 로그 핸들 정리 경합 2건으로 실패했다. 자식 종료까지 대기하도록 테스트 정리 코드만 수정 후 20개 전부 통과했다.
- Python 142개 회귀 테스트도 재통과했다. 전체 MARIA 1,436개 테스트를 다시 실행한 결과는 아니다.
- calendar-parity.json의 수정 해시는 현재·Git 원본·빌드 CSV 바이트와 일치하고 Python에서 13개 사례를 독립 대조했다. 계산 계약·해시 산식은 유지했다.

임시 MariaDB 11.8.9 전체 구조·합성 데이터 이관 3개도 통과했다.
기존 51개 테이블에 승인된 동기화 상태 테이블을 더한 52개 구조, 합성 종목·등급 77행·업무시계 1행을 사용했다.
재실행·중간 중단 후 복구·실패 ALTER의 기존 값 보존을 확인했다. 여러 DDL 전체 ROLLBACK을 보장한 것은 아니다.
운영 데이터 복사본이나 실제 운영 DB를 조회·변경하지 않았다.

## 남은 검증

- NCP ext4는 인프라 전달 결과다. 실제 볼륨 UID/GID·쓰기·배포 잠금·강제 종료·운영 복원은 미검증이다.
- 학원 VM 파일시스템·NFS 여부, 서버 밖 주간 백업 절차 확인.
- 실제 배포 공유 키와 동일 공식 달력 파일·해시 주입 확인. 로컬 인증 포함 실제 HTTP 재검증은 완료했다.
- 기존 공용 JDBC 풀 시간대를 바꾸기 전 SYSTEM_CLOCK 영향 확인. 위험등급 세션 UTC는 현재 차단 조건이다.
- 실제 15:40 반영 관측·달력 시간 갱신·확정 시드 원본 반영.
- 운영 DB 이관·NCP 배포·자동 동기화 활성화는 별도 승인 단계다.
